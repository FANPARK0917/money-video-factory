# 02 · 方法论：skill 工作流

> 来源：xilo2991 的开源 skill（`xilo-opus-video`）。
> 它不是渲染工具，而是一份**教 AI 做视频的方法论**：先有流程纪律，再谈渲染。

核心洞察一句话：**大模型不能直接输出视频，所以写一个"时间 t 决定画面"的程序，逐帧截图再用 FFmpeg 拼起来。**

---

## 标准五步

### ① 出 3 个方案（三选一）

接到主题后，先给 3 个不同角度的方案，每个包含：

- 一句话钩子（前 4 秒说什么）
- 3~4 个分点（每个带数字和情境）
- 收束方式
- 配色/风格关键词

**人只做选择题**，不做问答题。

### ② 定 brief

选定方案后，写成结构化 brief（模板见 [10](10-brief-template.md)）：

```yaml
主题: 4 个省钱习惯正在偷你的钱
总时长: 30s
结构:
  - 钩子 0-4s: "这 4 个省钱习惯，正在偷你的钱"
  - 点1 4-9s: 满减凑单（凑 99 减 20，多花 41）
  - 点2 9-14s: 便宜复购（9.9 包邮小拖把，3 个月坏 4 把）
  - 点3 14-19s: 大促囤货（双11 囤纸巾，放潮发霉扔一半）
  - 点4 19-24s: 付费会员（年费 198，一年用 3 次）
  - 收束 24-30s: "省"印章落下 + IP 头像弹出
配色: 暖纸底 #FFF7EA + 番茄红 #E8442E + 姜黄 #FFB800
字体: 站酷快乐体
BGM: 用户自选曲，截 30s + 结尾淡出
```

### ③ 逐幕写分镜代码

把 brief 翻译成可渲染代码。两条路线任选：

- **HTML 路线**：一个 `index.html` 暴露 `window.render(t)`（见 [03](03-route-html.md)）
- **Remotion 路线**：每幕一个 React 组件 + `<Sequence>`（见 [04](04-route-remotion.md)）

心智模型完全一样：`render(t)` ≈ Remotion 的 `useCurrentFrame()`。

### ④ 静帧 QA

**渲染前必须先出静帧**，每幕至少抽 1 帧检查：

- 构图：元素错位/旋转是否好看，有无重叠穿帮
- 文字：零错字（AI 生成中文最容易翻车的地方）
- 数字：每个数字有没有小票/算式/情境解释

静帧不过，**不许**进入全量渲染。

### ⑤ 全量渲染 + 三检

全量渲染后做三检（静帧复检 → 转场 → 响度），标准见 [01](01-pipeline.md) 阶段 5。

---

## 为什么这套流程有效

| 没流程时常犯的错 | 流程怎么防住 |
|---|---|
| 直接渲染 900 帧才发现错字 | ④ 静帧 QA 前置，错字在 1 帧的成本下暴露 |
| 改一幕，整片重渲 7 分钟 | 纯时间函数 + 分区间重渲 |
| 转场处残留旧版画面 | 三检中的转场闸：改场景必重渲相邻转场帧 |
| BGM 越放越大 | 三检中的响度闸（见 [06](06-audio.md)） |
| 题材重复 | brief 前先查 `used_topics.md` 黑名单 |

## skill 与 Remotion 的关系

skill 是"怎么组织工作"，Remotion 是"怎么渲染"。组合方式：

- skill 的 brief → Remotion 的 `<Composition>` + 每幕 `<Sequence>`
- skill 的静帧 QA → `npx remotion still`（原生支持，比手写截图脚本快）
- skill 的预览迭代 → Remotion Studio（浏览器里拖时间轴实时看）
- skill 的音频 → Remotion 的 `<Audio>` 原生支持

详见 [04](04-route-remotion.md)。
