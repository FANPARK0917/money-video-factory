# 09 · AI 接单指南：接到"做一条视频"后怎么做

> **这篇是写给 AI 智能体的。** 人类创作者看 [01](01-pipeline.md) 和 [02](02-method.md) 即可。
> 你的目标：用户只说一句话，你交付可直接发布的成片。

---

## 输入（向用户确认，最多问一次）

| 字段 | 说明 | 默认值 |
|---|---|---|
| 主题 | 这期讲什么 | 必填 |
| 时长 | 秒数 | ≤ 40s，默认 30s |
| 方向 | 横屏/竖屏 | 默认横屏 1920×1080 |
| BGM | 用哪首 | 默认用创作者当前 BGM（见 [07](07-assets.md)） |
| 要点 | 必须讲到的 3~4 个点 | 用户给，或你按 [01](01-pipeline.md) 阶段 2 调研后定 |

**开始渲染前**，必须先跟用户确认：讲述内容、配色、风格方案。
（已获长期授权的自动任务除外，如每日 6 点 cron。）

## 动作序列

```
1. 调研（实时搜索近期相关技巧/套路）
2. 查 used_topics.md，避开重复题材
3. 出 3 个方案给用户选（每方案：一句话钩子 + 分点 + 收束 + 配色关键词）
4. 按选中方案写 brief（模板见 10）
5. 写分镜代码（HTML 路线见 03 / Remotion 路线见 04）
6. 静帧 QA：每幕 ≥1 帧，检查构图/错字/重叠/数字情境
7. 全量渲染（改局部只重渲受影响区间 + 相邻转场帧）
8. 三检：静帧复检 → 转场 → 响度曲线
9. 音频：BGM 等长+淡出，numpy 叠音效（禁 amix 多输入）
10. 合成 → 新文件名交付 → 题材记入 used_topics.md
```

## 审美硬约束（违反 = 返工）

- 不用廉价合成 BGM、僵硬端正的字体、莫名悬浮数字、强广告感
- 偏好：活泼字体、错位/旋转/贴纸式排版、2.5D 层次动效
- 每个数字必须有小票、算式或具体消费情境解释
- 中文零错字（AI 生成中文案的第一杀手，静帧阶段重点查）

## 技术硬约束

- `render(t)` / 分镜组件必须是**纯函数**：同样输入同样输出，随机数 seeded
- 字体走本地 `@font-face`，不依赖 Google Fonts CDN
- 中间产物不放 `/tmp`
- 交付用**新文件名**（带版本号），防客户端缓存
- 音频：numpy 时域叠加，禁用 `amix` 多输入混音

## 交付检查清单（发之前逐项打勾）

- [ ] 时长 ≤ 40s，横屏 1920×1080，30fps
- [ ] BGM 与视频等长，结尾有淡出
- [ ] 无"前小后大"响度爬坡（2s 一段 RMS 曲线已查）
- [ ] 转场处无旧版残影
- [ ] 零错字，数字都有情境解释
- [ ] 文件名是新的（带版本号/日期）
- [ ] 题材已记入 used_topics.md
- [ ] 附一句话介绍当天题材

## 常见问题

**Q：用户说"纯 vibe，你定就行"？**
A：那就跳过第 3 步的用户选择，你自己定方案，但第 6 步静帧 QA 仍然要发给用户看（除非是已授权的自动任务）。

**Q：Remotion 渲染报 ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS？**
A：看 [05](05-browser-fix.md)，换 141 headless-shell，或切 HTML 路线走 `file://`。

**Q：用户想换 BGM / 改时间 / 暂停每日任务？**
A：BGM 换曲只接受用户主动通知；cron 的改动（暂停/改时间）直接执行并确认。
